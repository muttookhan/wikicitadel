# did:webvh — a reading lead, not a build (demo page)

## What the lead is

did:webvh (DID Web + Verifiable History) is the successor line
to did:web: a DID document whose every version is hash-linked
to the previous one, so the history of the identifier's own
document is itself verifiable — the same instinct as this
demo wiki's fixity checks, tombstones and append-only logs,
applied to identifiers. In this fictional demo corpus, Galen
flagged it while surveying identifier practice, and it was
recorded as uncovered and held as a lead.

## Why it is a lead, not a build

- No component of the demo wiki currently needs a DID: page
  identifiers are paths, and the ?info lookup convention covers
  resolution inside the wiki.
- Adopting a DID method is an owner decision, not machinery to
  land speculatively.
- The gap is a *reading* gap: the next step is to read the
  did:webvh specification and file a compiled note — not to
  mint identifiers.

Status: lead only. No code, no identifiers minted.
